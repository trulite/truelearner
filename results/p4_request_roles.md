# P4: Discovered request roles

Recorded: 2026-08-19

## Question

Can terminal task experience identify which anonymous identity-carrying event
functions as the request, without a query marker, receptor identity, parser
position or fixed serialization offset?

The request event appears at every serialization position. Its receptor ID,
opaque identity and surface encoding change. Request selection occurs before
program execution and answer emission. Terminal correctness updates only the
role trace that was already active.

When two anonymous events have identical observable structure, the learner
does not form a stable request preference.

## Fresh integration

Every P4c seed starts without:

- relation-field roles,
- a request role,
- working roles,
- control-event roles,
- program arrows,
- plasticity values.

The complete traversal task is present from the first episode. The same
lifetime discovers two relation roles, one request role, two working roles,
two control-event roles and the four-arrow recurrent program. Held-out
evaluation uses fresh identities and new sensory, working, event and request
encodings while learning is disabled.

## Interpretation boundary

P4 removes the target query marker. It still supplies:

- the distinction between relation components and anonymous identity-event
  components,
- observable local geometry that makes one event structurally distinguishable,
- broad sensory, working, event and output populations,
- exact structural signatures and comparison,
- generic operation effects,
- local plasticity, eligibility, correctness and pruning,
- opaque identity equality,
- `START` and explicit answer emission.

The result does not show that a request can be discovered when the environment
contains no observable distinction.
