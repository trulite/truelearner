## Preregistered local proposal physics

The only new capability is a generic basal local relation traversal. For each
ordinary observed directed propagation relation, the local proposal process:

1. encounters that relation through the raw adjacency traversal;
2. accepts it only when both endpoint CELLs are current actual E0 members and
   the same directed relation is present in actual E0 relative propagation;
3. derives an anonymous template from the endpoint-local temporal delta and
   directed local incidence only; and
4. records at most one support observation for that anonymous template in the
   episode, regardless of duplicate evidence or traversal order.

The traversal processes whatever relations the event contains. It has no
expected count, route table, legal-route list, role ordering, permutation list,
action enumeration, or special case for this fixture. It does not stop at two.
It may produce zero, one, two, or more proposals according to local physics.

Repeated support from three disjoint E0-formed support episodes consolidates a
template. Persistent state contains only endpoint-relative temporal delta,
directed local incidence, and primitive episode support. It contains no
OccurrenceId, CellId, concrete destination, episode, seed, expected count,
expected effect, action meaning, source/target/boundary role, route instance,
or evaluator value. Support generation is event-driven, local, semantics-blind,
and carries no negative evidence, credit, rank, or consequence.

At the target episode, the same traversal revisits every current supported
relation. Before any bridge exists, plasticity allocates a separate episode-local
root CELL, a separately owned bound continuation CELL, and a live directed
ARROW for that encountered relation. Each installed CELL binds only to its
current E0 member CELL and carries the bound CELL generation. Each root owns
distinct live adjacency. No route can be installed after or because of bridge
enumeration or DS1 need.

Execution injects a SPIKE at one already-installed root, validates generations,
and follows only live substrate adjacency. There is one generic adjacency
executor. No preassembled cell array, route opcode, handle switch, semantic
interpreter, or effect-directed operation exists.

## Structural and effect distinctness contract

Before bridging, the installer normalizes each live route to its sequence of
current E0 member bindings plus live directed adjacency. Normalization is
read-only and uses no execution effect. Routes with identical normalized live
adjacency are one structural affordance; later duplicates are rejected from the
root inventory and reclaimed. Different allocations or opaque route identities
do not create distinctness.

Each structurally unique root is then executed independently from an identical
frozen temporary start. The evaluator normalizes the execution to its current
bound-member trace and observable temporary E0-relative activation state. This
post-hoc trace/effect cannot feed learning, ranking, formation, installation,
structural deduplication, or the bridge. A counted affordance must have a
nonempty normalized effect distinct from every other counted affordance.
Effect-equivalent routes count once; the later duplicate is rejected from the
counted bridge inventory. Thus all of these count as one or are rejected:

- multiple handles to one root;
- copied roots with identical normalized live adjacency;
- different allocated identities with the same bound-member trace/effect; and
- structurally different routes with the same normalized observable effect.

The resulting affordance multiset must be invariant under bijective occurrence
relabeling, allocation order, memory layout, proposal observation order, route
installation order, and handle permutation.

## Opaque bridge boundary

Only after installation, structural deduplication, and independent post-hoc
effect distinctness evaluation may the bridge copy the accepted pre-existing
root references one-to-one into fresh opaque handles. The bridge may permute
references, but cannot create, execute, interpret, rank, label, or repair a
route. Every bridge entry has one unique live root; every accepted root has one
entry. Effect fingerprints and normalized traces are evaluator evidence and are
not stored in bridge entries.

The bridge exposes exactly the accepted physical roots, whatever their count.
It receives neither a minimum nor an expected count. No handle or route identity
is used as effect distinction.
