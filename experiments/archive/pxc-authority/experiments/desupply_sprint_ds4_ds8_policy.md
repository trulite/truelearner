# DS4--DS8 de-supply sprint policy

Status: **FROZEN RESEARCH-MANAGEMENT POLICY; NOT A SCIENTIFIC RESULT**.

This policy is separate from every definitive pass/fail protocol. It may guide
work scheduling and agent autonomy, but it is not evidence for DS3 or any later
de-supply claim.

## Operational mode

The main operational mode after a positive cumulative DS3 result is the
DS4--DS8 de-supply sprint:

```text
PARALLEL DEVELOPMENT

DS4 request/start
DS5 finish/output
DS6 lifetime/persistence
DS7 plasticity targeting
DS8 semantic credit


SERIAL AUTHORITY

M3
 ↓ DS4 cumulative
M4
 ↓ DS5 cumulative
M5
 ↓ DS6 cumulative
M6
 ↓ DS7 cumulative
M7
 ↓ DS8 cumulative
M8
```

Target preregistration, isolated mechanism audits, dependency scans, PROBE,
MICRO, diagnostic arms, and GATE hardening may run several generations ahead
in parallel. The authoritative cumulative prefix remains strictly serial. No
lane may claim `Mn+1`, run a cumulative definitive matrix, or consume a future
parent before `Mn` is frozen authoritative.

Before M3 exists, DS4--DS8 may begin target preregistration, isolated mapping,
dependency scanning, and non-authoritative development. Cumulative DS4 remains
blocked until M3 is authoritative.

## Target freezes

Preregister the removed supply and forbidden information for every remaining
target before mechanism development. Do not preregister a preferred repair or
representation.

```text
DS4  remove supplied request/start meaning
DS5  remove supplied finish/output meaning
DS6  remove supplied temporary/permanent lifetime classes
DS7  remove supplied plasticity-targeting/proposal policy
DS8  remove privileged semantic correct/wrong credit
```

Each target freeze must distinguish the removed organism-visible supply from
physical activity that remains lawful. It must name evaluator-only information
that may be used for scoring but can never reach acquisition, persistence,
selection, execution, or update paths.

## Standing autonomy instruction

Every development lane receives this instruction:

> Keep resolving mechanically forced dependencies without asking. Follow the
> first missing physical edge, reuse frozen mechanisms, freeze each repair,
> retry the unchanged downstream target, and continue. Stop only when there is
> an actual scientific ambiguity, a genuinely required new representation, or
> a semantic choice would be smuggled in. Return otherwise only at completed
> cumulative readiness.

The following are mechanical collapses and do not justify human escalation:

- missing spike, propagation, eligibility, proposal, or evidence-return path;
- an existing plastic mechanism not reached by ordinary activity;
- temporary binding or route exposure absent;
- stale compiled path or missing invalidation/reopening edge;
- work/lifetime cleanup not connected;
- a frozen mechanism present but not linked to the current parent.

The following do require escalation:

- two or more non-semantic developmental targets remain equally supported
  after controlled diagnostics;
- success requires choosing among incompatible representations with no frozen
  physical discriminator;
- a new persistent representation appears necessary;
- the only successful path restores forbidden meaning, identity, answer,
  correctness, or evaluator information;
- the cumulative parent lacks the physical phenomenon the frozen target needs.

## Mechanical linker workflow

Every cumulative port is treated first as a linker job:

```text
frozen downstream target
+ current authoritative parent
        ↓
automatic stage/path audit
        ↓
first missing physical edge
```

If one existing activity-to-mechanism edge is forced, close only that edge,
freeze it, and retry. Do not redesign the downstream mechanism.

If the audit leaves alternatives `A`, `B`, and `C`, preregister and run parallel
diagnostic arms against the same frozen downstream target:

```text
A ─┐
B ─┼─> frozen downstream mechanism and controls
C ─┘
```

Arm selection must use a preregistered, evaluator-blind physical criterion.
Engineering success alone cannot define the developmental target. If the
diagnostics do not uniquely select an arm, escalate the scientific ambiguity.

## Reusable dependency scanner

Build one source/path scanner that emits, for every frozen mechanism:

```text
requires:
  input relation
  executable path
  temporary state
  consequence edge
  update path

parent provides:
  present
  absent
  unresolved
```

The scanner reports syntax, call paths, storage, execution, and physical
reachability only. It may not assert semantic equivalence between differently
named signals. `unresolved` must remain unresolved until a runtime probe or
information-flow audit decides it.

Runtime probes remain mandatory; static presence never substitutes for actual
organism-visible execution.

## Development ceremony

Scientific ceremony remains strict while engineering ceremony scales with
evidence:

```text
PROBE  one seed; path existence; smallest decisive controls
MICRO  roughly two seeds; minimal transfer and leak controls
GATE   full development readiness and hardened control battery
DEF    separate single frozen authoritative matrix
```

Most zero-edge mechanisms should stop at PROBE. Do not build a large harness
before the next downstream physical edge exists. Once composition survives,
harden it through MICRO and GATE.

## Freeze, port, and rebase discipline

An isolated lane that becomes development-ready before its authoritative
parent exists freezes its mechanism and controls. When the parent arrives:

```text
frozen isolated mechanism
+ new authoritative parent
        ↓
unchanged cumulative port
        ↓
dependency probe
        ↓
resolve only the delta
```

Downstream lanes rebase their wiring onto the new parent; they do not redesign
their mechanism for it. Each repair receives its own protocol/freeze before the
unchanged target is retried.

## Definitive authority separation

A development lane stops at a clean readiness ancestor with:

- every cumulative stage ready;
- every frozen control passing;
- all upstream mechanism hashes exact;
- no definitive artifacts;
- a clean worktree.

A separate authority phase then verifies hashes, freezes the definitive
protocol, performs bounded non-claim preflight, runs the matrix once on E2B,
freezes write-once artifacts and outcome, and advances `Mn` only on a complete
conjunctive pass.

No development lane may rerun, tune, rescue, or reinterpret a definitive
result. Parallel development never weakens serial authority.

## Human interaction budget

Humans should normally receive only:

```text
COMPLETED
  DSn cumulative ready/passed; Mn advanced if definitive

SCIENTIFIC AMBIGUITY
  exact missing dependency
  competing non-semantic derivations
  diagnostic evidence that failed to distinguish them
```

Mechanical missing edges remain autonomous work. This policy optimizes cycle
time; it does not alter any scientific claim or pass threshold.
