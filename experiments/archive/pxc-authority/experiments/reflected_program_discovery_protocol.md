## One question and no new learner

Can the same local learning physics that constructs a recurrent procedure over
external experience construct an executable recurrent procedure over anonymous
roles learned from one level of internal execution provenance?

```text
substrate-native lower computation
    -> anonymous consume/produce provenance
    -> recurring reflected roles
    -> unchanged P0-style local program learning
    -> executable reflected procedure
```

The permitted positive claim is narrow:

> The same local program-learning physics that constructs procedures over
> external experience constructed an executable recurrent procedure over
> anonymous roles learned from internal computation.

RP0a does not claim arbitrary compiler discovery, arithmetic discovery,
reflection economics, real d2.6 substitution, or recursive reflection.

## Frozen lower computation

The lower task is the frozen v19-v21 chain traversal family, not address-score
arithmetic. Its already established generic substrate physics includes:

- temporary opaque identity occurrences and `SAME`;
- relation lookup through temporary binding;
- queued spike delivery until quiescence;
- result feedback into temporary current state;
- continuation by reactivating application;
- no-result and explicit finish;
- one external start and an explicit output boundary.

Training chains have depths `1, 2, 3, 4`; held-out chains have depths
`5, 8, 16, 32`. Each chain also contains eight irrelevant relations. The
lower execution is expressed as actual local cells, arrows, spikes, temporary
occurrences, and queue transitions. It may not be replaced by a host-side
answer function or by the opaque Rust arithmetic that blocked F0.3c.

The runtime has ten functional locations corresponding evaluator-side to the
P0 role vocabulary. Those meanings never cross the learner boundary. Every
episode assigns fresh opaque source and occurrence identities, permutes
serialization, and records only generic local causal incidence.

- P3's named working/event roles or a semantic population label;

Role names and the four correct arrows exist only in the evaluator for scoring.

## Anonymous provenance and reflected roles

Each lower local activation emits a one-level record containing only:

- a fresh opaque activity-source identity;
- fresh opaque temporary occurrences consumed;
- fresh opaque temporary occurrences produced;
- causal direction and episode-local occurrence equality;
- generic boundary facts already available to local execution.

Raw opaque payload values, semantic cell identities, operation names, answers,
and terminal correctness are absent. Trace processing cannot itself emit
another trace.

The role learner receives unordered generic local provenance neighborhoods.
Repeated structural signatures recruit persistent role cells after four
observations. Permanent role state stores signatures and support, never source
or occurrence identities. Fresh encodings must reactivate the same learned role
cells. When two evaluator roles are made structurally symmetric, the learner
must not invent a distinction.

There is no semantic adapter between role formation and program formation.
During execution, a learned role cell binds temporarily to the fresh lower
location whose current provenance activates it. Program arrows connect learned
role cells; their spikes reach lower locations only through that temporary
binding.

## Unchanged program-learning pressure

Once reflected roles become active, generic coactivity proposes both directions
between nearby active role cells. All proposals receive the frozen P0
probation, trace, terminal credit, consolidation, and pruning physics. The
learner is never told which sources require outgoing arrows or how many program
arrows exist.

The complete chain task is present from episode one. There is no isolated-role
or staged program curriculum in the integrated arm. Only arrows that actually
carried queued activity receive the episode's terminal correctness credit.

Every integrated learner starts without inherited reflected roles, program
arrows, values, or candidate topology. Training ends after competence or the
frozen `50,000`-episode budget. Learned topology must contain the four
evaluator-correct recurrent routes and must execute rather than call an oracle
or fall back to the supplied lower program.

## Arms and controls

A. **Frozen base anchor.** Unchanged public P0 and P3 experiments. This localizes
whether a failure is new composition rather than broken ancestors.

B. **RP0a integrated.** Generic provenance, learned anonymous reflected roles,
and P0-style program learning from terminal correctness.

C. **Activity only.** Same opaque source activity and event load without
consume/produce incidence.

D. **Shuffled provenance.** Provenance neighborhoods are paired with the wrong
fresh lower locations, using a seed domain independent of task outcomes.

E. **Shuffled terminal feedback.** Correct execution and provenance, but each
episode receives the preceding episode's terminal outcome.

F. **Random terminal feedback.** Correct execution and provenance with
independent deterministic random credit.

G. **Symmetric impossible roles.** Two functionally required lower locations
have identical observable provenance structure. No stable distinction may
form, and competence is not expected.

H. **Oracle reflected roles and program.** Read-only diagnostic upper bound.
It uses the same lower runtime and work accounting but supplies the applicable
role bindings and four correct arrows. Oracle information never enters B-G.

## Matrix and held-out evaluation

Definitive seeds: `0..8`. Training depths rotate `1, 2, 3, 4`. Checkpoints are
`0, 1, 2, 4, 8, 16, 64, 256, 1024, 10000, 50000` plus first role, first actual
success, each consolidation, and competence.

After training, freeze role support, topology, strengths, parameters, and lower
state. Evaluate 16 fresh episodes at each held-out depth `5, 8, 16, 32`, with
fresh opaque identities, fresh activity-source identities, fresh occurrence
identities, and transferred serialization. No role or program learning occurs.

Record:

- learned roles, supports, source/occurrence identity retention, and transfer;
- proposed, used, consolidated, pruned, and live arrows;
- actual lower cells touched and every reflected binding;
- external and internal spikes, arrow evaluations/firings, queue operations,
  temporary cells/arrows, comparisons, role matching, learning work, runtime
  work, and permanent bytes;
- explicit answer, queue quiescence, activity-limit hits, false role
  activations, fallback/oracle calls, fingerprints, and lifecycle destruction.

RP0a has no charged byte price or break-even. Economics remains blocked.

## Conjunctive gate

RP0a passes only if all twelve conditions hold:

1. **Frozen ancestry and isolation.** Parent and all hashes above match; no
   frozen source, result, tag, trunk, tau, d2, or F0 branch changes.
2. **Substrate-native execution.** Oracle executes every probe correctly
   through cells/arrows/spikes with one external start, explicit answer,
   quiescence, and zero concrete/host fallback.
3. **Opaque reflected boundary.** No forbidden identity, value, role, event,
   route, phase, target, operation, answer, or correctness field crosses into
   role or program learning.
4. **Anonymous role formation.** Every integrated seed learns all required
   distinct reflected roles and transfers them perfectly to fresh source and
   occurrence encodings while retaining zero concrete identities.
5. **Impossible-role discipline.** The symmetric control forms no stable
   distinction between the indistinguishable required roles and does not
   become competent.
6. **Frozen positive anchors.** Public P0 and P3 remain fully positive with
   their frozen expected held-out behavior.
7. **Fresh integrated competence.** All eight RP0a seeds construct a functional
   recurrent program without inherited roles/arrows within 50,000 episodes.
8. **Held-out execution transfer.** RP0a answers `512/512` held-out chains,
   emits explicit answers, empties every queue naturally, and hits no activity
   limit or fallback.
9. **Learned topology.** Every successful learner retains exactly the four
   evaluator-correct program arrows; arrows emerged only after role support and
   were selected through ordinary terminal credit.
10. **Controls discriminate.** Activity-only, shuffled-provenance,
    shuffled-feedback, and random-feedback arms each have zero competent seeds
    and materially less correct held-out behavior than RP0a.
11. **Read-only determinism.** Duplicate held-out evaluation is identical;
    every permanent fingerprint remains unchanged and all temporary state is
    erased.
12. **Accounting and lifecycle.** Every row reconciles; all reflected and lower
    work/storage is counted; every workspace is destroyed and maximum live
    temporary state returns to zero.

A role representation without an executable learned program is negative. A
correct program that uses oracle/fallback execution is negative. Accuracy from
inherited semantic roles is invalid.
