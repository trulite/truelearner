# PX0-R generic physical correspondence reproposal protocol

Status: **development preregistration; no PX0 authority evidence spent**.

PX0-v1 remains immutable at tag
`px0-physical-correspondence-development-readiness`, commit
`17fe7fa36d932e932ad4f9bb5fffc1a83326f9f5`.

## Research question

> After previously useful correspondence structure has reached zero
> resistance and is physically non-live, can renewed anonymous local activity
> form fresh candidate structure through a uniform substrate-native
> opportunity law, allowing ordinary returned activity to select a useful
> correspondence again?

## Required physical sequence

```text
old arrow resistance reaches zero
        ↓
old generation is stale and non-executable
        ↓
renewed anonymous local activity
        ↓
generic adjacency-limited variation creates a fresh arrow identity
        ↓
ordinary physical return reaches only currently eligible structure
        ↓
supported fresh structure persists; unsupported structure disappears
        ↓
fresh activity executes the newly retained structure
```

The old arrow may remain in evaluator-visible storage as a dead historical
physical object. It must never become live again. Reacquisition requires a new
`ArrowId` and a fresh generation-bearing object.

## Frozen active-state restriction

PX0-R inherits every PX0 active-state and anti-representation rule. Active
state may contain only ordinary CELL/ARROW/SPIKE state and local physical
timing/eligibility. It may not contain a motif, relation key, remembered
answer, proposal class, episode/history object, route label, correctness
signal, or renamed equivalent.

The old M0 and PX0-v1 implementations are evaluator/reference ancestors only.
PX0-R must not import or call them as active mechanisms.

## Generic opportunity law

Any new structural proposal must be caused by the same local physical rule for
all fresh identities and layouts. It may use only:

- an ordinary external spike that physically makes a cell fire;
- current local cell positions/regions and a fixed adjacency radius;
- absence of a live arrow between physically adjacent cells;
- fresh allocation identity;
- the existing scalar pressure, eligibility, and returned-activity dynamics.

It may not use the dead arrow's old identity, endpoints, coupling, strength,
eligibility, consequence history, or generation as a template. Dead arrows
must be ignored when selecting fresh endpoints; the endpoint opportunity must
be rediscovered from current live cell adjacency.

The evaluator/world may provide ordinary background activity that makes broad
local variation physically executable without making it an outward answer.
It may provide ordinary device activity that changes which downstream return
path is physically supported. It may not name a candidate or mutate a chosen
arrow.

## Conjunctive behavioral requirements

1. Initial ordinary experience acquires one physical correspondence.
2. Sufficient ordinary pressure makes every variable arrow supporting that
   correspondence reach resistance zero.
3. Every old variable arrow is non-live and cannot execute a stale queued
   occurrence.
4. No renewed source activity produces no new arrow and no resurrection.
5. Renewed anonymous source activity creates fresh candidate arrows through
   current adjacency.
6. Every reacquired retained arrow has a new physical `ArrowId`.
7. Ordinary timely return retains the fresh useful structure.
8. Unsupported fresh candidates disappear under unchanged pressure.
9. Held-out fresh activity restores exactly the selected outward behavior.
10. Renewed ambiguous return produces no privileged reacquisition or arbitrary
    outward winner.
11. If the physical return world changes before renewed experience, the newly
    retained correspondence follows the new world rather than the historical
    answer.
12. Absent return causes fresh candidates to disappear.
13. Fresh namespaces, identities, layout/allocation permutations, route
    mirrors, and arrival-order permutations preserve the law.
14. Complete physical duplicates replay exactly.
15. Activity becomes naturally quiescent without reset.
16. Work, storage, proposal count, deallocation count, and fresh identity are
    explicitly accounted.

## Hard anti-cheat controls

- Re-enabling the old arrow or decrementing its generation is failure.
- Copying endpoints from dead arrows is failure.
- An evaluator call such as `repropose(route)` or `restore(arrow)` is failure.
- A dormant semantic route template is failure even if stored as CELL state.
- A proposal must be available for physically adjacent alternatives
  uniformly, including alternatives that never receive return.
- Same candidate opportunity with opposite physical return support must learn
  the opposite survivor.
- Removing renewed activity must yield zero proposals.
- A stale in-flight spike carrying the dead generation must remain blocked.

## Development stages

### PROBE

One fresh namespace. Acquire one route, physically deallocate it, verify stale
non-execution, provide renewed local activity, and require a fresh arrow
identity plus restored held-out behavior. Include absent-renewal and
opposite-return arms.

### MICRO

Approximately two fresh namespaces with route mirror, allocation permutation,
ambiguous return, absent return, changed return world, duplicate replay, and
work/storage accounting. The physical law must remain byte-identical to the
positive PROBE.

### GATE

Fresh namespaces across candidate abundance, selected-route positions,
layouts, timing schedules, and return worlds. All sixteen requirements are
conjunctive. Static source/dependency audits and frozen PX0-v1 hashes must
pass. No definitive command is authorized.

## Classifications

- **PX0-R-A:** generic fresh-identity physical reproposal positive.
- **PX0-R-B:** lawful generic proposals form but behavioral reacquisition
  fails.
- **PX0-R-C:** reacquisition requires historical resurrection,
  evaluator-selected mutation, or a forbidden representation.
- **PX0-R-D:** more than one scientifically distinct opportunity law remains
  equally plausible and current physical evidence cannot distinguish them.

## Program consequence

A positive PX0-R GATE creates combined PX0 authority readiness only. A later
separate authority workflow must preregister a single fresh matrix covering
PX0 acquisition, survival-window reuse, full deallocation, and generic
fresh-identity reacquisition. PX1 and Harness H1 remain blocked until that
definitive matrix passes once.
